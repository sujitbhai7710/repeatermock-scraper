Recovery cap (20 attempts) + skip impossible auto-logins in CI + safer startup rotation

- wait_for_live_account now STOPS after MAX_RECOVERY_ATTEMPTS (default 20)
  failed cycles: saves scraped progress, exits code 2 (red run) instead of
  looping uselessly until the time limit.
- Chrome CDP + Google-profile auto-login paths are skipped on GitHub Actions
  (no user Chrome/profile exists there - they could never succeed and spammed
  every 90s recovery cycle).
- Startup force-refresh threshold raised 3 min -> 5 min: starting a 40-min
  scrape with 3.1 min of token life guaranteed mid-run session_expired 401s.

NOTE on token deaths: RepeaterMock kills the ENTIRE refresh-token family when
a consumed token is replayed (classic reuse detection). The browser
auto-refreshing with a stale exported token (~15 min after export) is what
has been killing freshly-deposited chains, not the scraper.
