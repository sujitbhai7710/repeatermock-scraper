Fix zombie worker contexts after recovery (W1 "browser has been closed" storm)

Live-run evidence: auth + refresh chain work (workers W0/W2 fully
scraped tests with solutions + analysis), but worker W1 failed EVERY
test with "Target page, context or browser has been closed" and
marked them all FAILED.

Root cause: wait_for_live_account() closes and replaces the shared
browser during recovery, but never bumped session_generation — so
workers whose generation still "matched" never rebuilt their contexts
and kept using the closed browser until the run ended.

Fixes:
- Every successful recovery path now bumps session_generation so all
  workers rebuild their contexts on the new browser.
- worker_loop also defensively rebuilds when its context's browser is
  disconnected, even if the generation matches.

Failed-marked tests are re-queued automatically on the next run.
